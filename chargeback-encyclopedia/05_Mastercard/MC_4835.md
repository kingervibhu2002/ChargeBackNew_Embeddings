# Mastercard 4835 — Card Not Valid or Expired

## Definition

Mastercard reason code 4835 is filed when a transaction was processed on a card that was expired or otherwise invalid at the time of the transaction. The central issue is that the merchant accepted a card that should not have been accepted, either because its expiration date had passed or because the card had been canceled, invalidated, or revoked.

This code is relatively rare in environments with proper electronic authorization because modern authorization systems check card validity — including expiration dates — automatically. Its appearance typically signals a gap in authorization procedures.

## When This Reason Code Applies

4835 applies in these situations:

- **Expired Card Accepted**: The card's expiration date had passed at the time of the transaction, and the merchant processed it anyway.
- **No Expiration Date Verification**: The merchant manually accepted a card without verifying the expiration date (common in MOTO or phone-order scenarios).
- **Invalid Card Number**: The card had been canceled or replaced, and the old number was used without proper verification.
- **Authorization Approved Despite Expired Card**: In some cases, an authorization system incorrectly approves a transaction on an expired card. However, if the authorization system returned an approval, merchant liability is significantly reduced.
- **Manually Processed Without Electronic Authorization**: Merchants using manual imprinters or offline processing did not have the benefit of real-time expiration validation.

## Understanding Authorization Response Codes

The cornerstone of a 4835 defense is the authorization response. Modern authorization systems check:

1. Whether the card number is valid and active
2. Whether the expiration date has passed
3. Whether the card is on any exception or warning list
4. Whether the transaction amount is approvable

**If the authorization system returned an approval code**, the issuer effectively confirmed at that moment that the card was valid. A subsequent 4835 chargeback based on expiration would be a weak claim on the issuer's part, and the merchant's Second Presentment citing the authorization approval should succeed.

**If no electronic authorization was obtained** (manual, forced, or offline transaction), the merchant had no automated safety check and bears liability for accepting an expired card.

## Authorization Response Codes Relevant to 4835

| Response Code | Meaning | Implication |
|---|---|---|
| 00 (Approved) | Card valid, transaction approved | Strongest defense against 4835 |
| 54 (Expired Card) | System explicitly detected expiration | Merchant should not have processed |
| 14 (Invalid Card Number) | Card number not valid | Do not process |
| 05 (Do Not Honor) | Issuer declined for unspecified reason | Do not process |

A response code of 54 is a clear signal that the system flagged the card as expired. Processing the transaction after receiving code 54 — or overriding the decline — eliminates any defense.

## Electronic vs. Manual Expiration Check

**Electronic Authorization (Standard)**:
The authorization network automatically validates the expiration date. If the card is expired, the response will be code 54. If the response is code 00 (Approved), the system has validated the expiration date, and the merchant is protected.

**Manual Check (MOTO/Phone Orders)**:
When processing phone orders, merchants ask the cardholder for the expiration date and manually verify it. The risk here is human error — transcription mistakes, or a cardholder providing an old expiration date.

**Manual Imprinter (Legacy)**:
Physical imprinter ("zip-zap") transactions require the cashier to visually inspect the expiration date embossed on the card. Missing or ignoring an expired date during manual processing creates full merchant liability.

## Common Scenarios

**Scenario 1: Phone Order with Old Card Details**
A repeat customer calls to place an order using card details stored in a notebook. The card was replaced 6 months ago, and the customer accidentally provides the old expiration date. The merchant processes the order without verifying against the current card, and the transaction fails post-authorization verification.

**Scenario 2: Cashier Ignores Expiration**
A customer presents an expired card at a retail location. The cashier notices the expiration date but processes the transaction anyway because the card "still swipes." The POS system's magnetic stripe reader does not validate expiration date — only the authorization system does, and in this case, no full authorization was obtained.

**Scenario 3: System Override**
A POS system returns code 54 (Expired Card) on the first attempt. The cashier — believing this to be a system error — forces the transaction through using a manual override code. The chargeback is filed and the merchant has no defense.

**Scenario 4: Subscription Billing**
A merchant has stored card credentials for a subscription service. The card was renewed by the issuer with the same number but a new expiration date. The merchant continues billing the old expiration date. Initially, some transactions may pass if the issuer applies account updater logic, but eventually a 4835 is filed.

## Merchant Liability

Merchant liability is **high** when:
- A manual authorization was done without verifying the expiration date
- An expired card was accepted despite a code 54 decline
- A forced transaction was processed after an expiration decline

Merchant liability is **low or eliminated** when:
- A valid electronic authorization with an approval code (00) was obtained
- The issuer's system approved the transaction without returning a code 54
- An Account Updater service was in use and the transaction was processed with the updated credentials

## Required Evidence

1. **Electronic Authorization Record**: Approval code, date, time, and response code. If response was 00 (Approved), this is your primary defense.
2. **POS or Gateway Transaction Log**: Confirming the authorization path and response.
3. **Account Updater Records**: If applicable, evidence that your system retrieved updated card credentials before processing.
4. **MOTO Order Documentation**: For phone orders, the order form with the expiration date the customer provided.

## Winning Strategy

1. **Lead with the authorization approval code.** If your authorization system returned code 00, the issuer confirmed card validity at that moment. Your Second Presentment should center on this fact.

2. **Show Account Updater compliance for subscription merchants.** If you use Mastercard's Account Updater or equivalent service, demonstrate that updated credentials were retrieved and applied before each billing cycle.

3. **For MOTO disputes**: Show the order form or call log where the customer provided the expiration date. If the customer provided an incorrect date, the cardholder bears some responsibility.

## Losing Mistakes

- **Processing after a code 54 decline**: This is indefensible.
- **Using stored credentials without Account Updater**: Always refresh stored card credentials before recurring billing.
- **Manual processing without expiration verification**: Train staff to check expiration dates on every manual transaction.
- **Assuming the magnetic stripe validates expiration**: Magnetic stripes do not validate expiration dates — only the authorization network does.

## Timeline

| Event | Deadline |
|---|---|
| Chargeback filed by issuer | Within 120 days of transaction |
| Merchant Second Presentment | Within 45 days of chargeback |

## Prevention Checklist

- Always obtain full electronic authorization — never force or bypass the authorization system.
- Train staff to check card expiration dates on every card-present transaction.
- For subscription merchants, enroll in Mastercard Account Updater to automatically refresh stored credentials.
- Configure your POS to hard-decline transactions that return code 54 — no override permitted.
- For MOTO processing, build expiration date field validation into your order form workflow.

## Frequently Asked Questions

**Q: The issuer approved the transaction but is now disputing it as expired. Can they do that?**
A: If the authorization returned a genuine approval code (00) and is verifiable in your system logs, this is a strong defense. The issuer's approval constitutes their confirmation of card validity at that moment. Present the authorization record in your Second Presentment.

**Q: We charge subscriptions monthly. How do we prevent 4835 disputes?**
A: Enroll in an Account Updater service (Mastercard provides one) to automatically receive updated card credentials when cards are replaced or renewed. Also implement a proactive card-on-file refresh cycle before billing.

**Q: My POS system doesn't check expiration dates electronically. What should I do?**
A: Upgrade to a compliant POS system that routes every transaction through electronic authorization. Until then, train staff to manually verify expiration dates on every card-present transaction and document this in your procedures.
