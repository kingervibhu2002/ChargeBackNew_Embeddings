# Mastercard 4807 — Warning Bulletin

## Definition

Mastercard reason code 4807 is issued when a merchant completes a transaction on a card that appears on the Warning Bulletin — Mastercard's list of cards flagged as stolen, lost, counterfeit, or otherwise compromised. The fundamental allegation is that the merchant either failed to check this list or ignored the warning and processed the transaction anyway.

In the modern payments era, this code is rare because electronic authorization systems automatically check cards against exception files in real time. However, it remains relevant in specific scenarios where electronic authorization was bypassed or unavailable.

## When This Reason Code Applies

Code 4807 is triggered in the following circumstances:

- **Manual Key-Entry Without Authorization**: The merchant manually keyed a transaction and did not obtain a proper electronic authorization, allowing a flagged card to slip through.
- **Paper Voucher or Manual Imprinter Transactions**: Older fallback processing using manual imprinters (zip-zap machines) did not have access to real-time exception file checking.
- **System Outage / Forced Transactions**: During a POS system outage, a merchant processed a transaction offline ("forced") without checking the exception file.
- **Historical Transactions**: The code may appear on chargebacks for older transactions processed before electronic authorization was universal.

## Why Electronic Authorization Makes This Rare

Every time a merchant submits a transaction for electronic authorization, the payment network checks the card number against its exception file — a real-time database of compromised and flagged cards. If the card is on the Warning Bulletin, the authorization request returns a **Decline (05)** or **Pick Up Card (04)** response code.

A legitimate electronic authorization with an approval code is the merchant's primary shield against a 4807 chargeback. If the authorization was electronically approved, it means the card was not on the exception file at the time of the transaction. This is a strong defense.

## Common Scenarios

**Scenario 1: Fallback Transaction**
A chip card's EMV chip fails repeatedly, and the cashier swipes the magnetic stripe as a fallback. If the system does not route this through a proper authorization, a 4807 dispute can arise.

**Scenario 2: Force-Posting a Transaction**
A manager overrides a declined transaction using a forced transaction code, bypassing the authorization system. If the card was on the Warning Bulletin, the merchant bears full liability.

**Scenario 3: Manual Authorization via Voice**
The merchant called for a voice authorization but was given incorrect or outdated information, or failed to receive an authorization code altogether.

## Merchant Liability

Merchant liability under 4807 is **very high** when:
- No valid electronic authorization code exists
- The merchant processed a forced or offline transaction
- The card was physically on a paper exception bulletin that the merchant ignored

Merchant liability is **low or eliminated** when:
- A valid electronic authorization approval code was obtained
- The authorization response was "Approved" at the time of the transaction
- System logs confirm the authorization was processed through standard channels

## Required Evidence

To contest a 4807 chargeback, merchants must provide:

1. **Authorization Approval Code**: The 6-digit code returned by the issuer at the time of authorization. This is the single most important piece of evidence.
2. **Transaction Log / Authorization Record**: A printout or system export showing the authorization request, response, date, time, and approval code.
3. **POS System Data**: If the transaction was processed during an outage, documentation of the outage and the merchant's standard offline procedures.
4. **Voice Authorization Records**: If authorized by phone, the authorization code and the name/employee ID of who obtained it.

## Winning Strategy

1. **Lead with the authorization approval code.** If you have a valid approval, your response should be built around this single fact. Submit the transaction log, the receipt showing the authorization code, and a brief rebuttal letter stating the card was electronically authorized and approved.

2. **Do not attempt to fight if no authorization exists.** If the transaction was genuinely forced without checking the exception file, fighting the chargeback is likely futile and wastes resources.

3. **Demonstrate systematic compliance.** If you process a high volume of transactions, showing that your systems automatically route every transaction through electronic authorization (e.g., excerpts from your POS configuration or acquirer processing agreement) strengthens your position.

## Losing Mistakes

- **Submitting evidence of a voice authorization without an approval code**: A record of calling for authorization is not the same as a record of receiving an approval.
- **Assuming a receipt is sufficient**: The customer receipt alone does not prove authorization. The authorization record from your payment system is required.
- **Missing the response deadline**: Merchants have 45 days to respond. Missing this window forfeits any defense regardless of how strong the evidence is.
- **Fighting a legitimately forced transaction**: If a manager truly bypassed authorization, the chargeback is valid. Fighting it without a valid authorization code results in additional fees and no recovery.

## Timeline

| Event | Deadline |
|---|---|
| Chargeback filed by issuer | Within 120 days of transaction |
| Merchant Second Presentment | Within 45 days of chargeback |
| Pre-Arbitration (if issuer rejects) | Within 45 days of Second Presentment |

## Prevention Checklist

- Ensure every transaction goes through electronic authorization — no exceptions.
- Train staff never to force-post transactions on declined cards without manager authorization and escalation to the acquiring bank.
- Disable manual fallback processing unless absolutely necessary, and audit fallback transaction logs regularly.
- Configure POS systems to decline (not allow) transactions if authorization is unavailable during an outage, or implement a strict offline floor limit policy.

## Frequently Asked Questions

**Q: If I got an authorization approval, can the issuer still file a 4807?**
A: Technically yes, but your Second Presentment citing the valid authorization code and transaction log should result in the chargeback being reversed. The approval code is strong evidence that the card was not on the Warning Bulletin at the time.

**Q: Are Warning Bulletins still relevant in today's market?**
A: The formal paper Warning Bulletin is largely obsolete, but the underlying concept — exception file checking — is integral to every electronic authorization. The reason code persists for scenarios where that check was bypassed.

**Q: What does a "Pick Up Card" authorization response mean?**
A: Code 04 means the issuer is instructing the merchant to physically retain the card. Processing the transaction after receiving this response dramatically increases liability and can constitute a violation of Mastercard's operating rules.
